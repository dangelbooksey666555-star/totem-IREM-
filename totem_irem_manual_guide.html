总体流程图

从用户视角，真正需要掌握的是：先确认分析模式，再分别准备电学模型、物理模型和封装模型，最后让 GSR/TCL 把它们调度起来。

静态 IREM 的本质

静态分析并不追踪真实时域波形，而是把功耗/电流以平均值或区域/层次分配方式压到 P/G 网络上，再结合提取后的电阻网络求 IR drop，并顺手做静态 Power EM。

动态 IREM 的本质

动态分析先通过 APLMMX + Spice 把器件端口电流变成 `spcurrent/cdev`，再在提取出的 RLC 网络上跑瞬态，得到真实的动态压降与动态 EM。

Signal EM 的本质

Signal EM 把“谁在驱动哪根信号网、这根网的瞬态/估计电流多大、线宽与 via 规则允许多大电流密度”组合起来，检查信号线而不是 P/G 网。

01 选模式 先决定是做静态、动态、Power EM 还是 Signal EM。这个决定直接影响你到底需要平均功耗、瞬态波形还是信号网 RC。
02 做电学预表征 APLMMX 读取网表、模型库、testbench、波形，生成 probe、`spcurrent`、`cdev`、`gdsmmx`。
03 做几何建模 GDS2DB 读取 GDS、layer map、top cell、net tracing 信息，构建几何与连通性。
04 接入封装 对动态压降或更真实的电源网络，继续叠加 pad / wirebond / package 的 RLC 或 RLCK 子电路。
05 运行分析 `pwrcalc → extraction → gridcheck → analysis`；Power EM 和 Signal EM 则在各自结果上继续检查。

输入数据准备清单

这一节回答三个问题：要准备什么、为什么要准备、它会被哪一个节点消费。用户最容易在这一层把“文件存在”误当成“格式可用”。

电学输入

文件 / 数据 被谁用 用途
`SPICE_NETLIST` / `LAYOUT_NETLIST` / `DSPF_NETLIST` APLMMX / Signal EM 识别器件、端口、层次名和 RC 坐标，建立器件到物理位置的映射。Chapter 3 p.71-73, p.367-376。
`DEVICE_MODEL_LIBRARY` APLMMX / Signal EM 给器件类型与工艺角，支撑 drive strength、Idsat、Spice 预表征。Chapter 3 p.70-73, p.374-380。
`TOP_CELL` / `TOP_XCELL_NAME` APLMMX 前者定义分析顶层 subckt，后者决定 probe 在 testbench 里的层次前缀。Chapter 3 p.73。
`TEST_BENCH_FILE` 动态 IREM / Signal EM 提供激励与仿真环境。Signal EM 明确要求单独指定，不能只藏在 include 里。Chapter 11 p.374-381。
`SIM_OUTPUT_FILE` APLMMX `-n` / `-sig -n` 把 Spice 波形导回 APLMMX，生成 `spcurrent/cdev` 或 signal EM 电流模型。Chapter 3 p.64-65, Chapter 11 p.374-381。

物理与网络输入

文件 / 数据 被谁用 用途
`GDS_FILE` + `GDS_MAP_FILE` GDS2DB / Signal EM 构建金属、via、device pin snapping 和 net tracing；layer map 决定 GDS 层号怎样翻译成工艺层。Chapter 3 p.137-148。
`TOP_CELL` / `TOP_CELLS` GDS2DB 告诉 GDS2DB 从哪一个几何层次开始抽取。Chapter 3 p.140。
`VDD_NETS` / `GND_NETS` GDS2DB / GSR / EM 一方面定义电源域电压，另一方面给 GDS tracing 指定要跟踪的电源网名或坐标。Chapter 3 p.146-148, Chapter 4 p.197-210。
`TECH_FILE` Static / Dynamic / EM / Signal EM 提供金属厚度、电阻、电容、EM limit、温度基准。Chapter 4 p.197, p.208-210, Chapter 11 p.370-389。
`USE_TOP_LEVEL_TEXT_ONLY 1` 等 tracing 调试设置 GDS2DB 短路、坐标、label 不可靠时的第一批排错抓手。Chapter 3 p.185-187。

分析控制输入

文件 / 数据 被谁用 用途
`BLOCK_POWER_FOR_SCALING` / `BLOCK_POWER_ASSIGNMENT` 静态 IREM 决定静态电流如何分配到电源网络；没有真实动态波形时，这就是电流注入的来源。Chapter 4 p.197-201。
`APL_FILES` 动态 IREM 把 `spcurrent` 与 `cdev` 导入 Totem；这是动态分析的核心电流源模型。Chapter 4 p.202-204。
`USER_STA_FILE` 动态 IREM 给实例 timing window。Chapter 4 p.202-203。
`GSC_FILE` 动态 IREM / Signal EM 指定 switching state，决定分析用哪一个状态或多状态窗口。Chapter 4 p.202-203, Chapter 11 p.380-381。
`DYNAMIC_SIMULATION_TIME` / `DYNAMIC_TIME_STEP` 动态 IREM / Signal EM 控制瞬态仿真的总时长与步进；`pwrcalc` 还会给出推荐的动态分析时间。Chapter 4 p.189, p.202-203, Chapter 11 p.380。

封装与扩展输入

文件 / 数据 被谁用 用途
`.ploc` 动态 IREM / Package 把 die pad 位置和 package 端口名连起来；有 package subckt 时格式必须带 domain 和 port name。Chapter 7 p.278。
simple pad/wirebond/package RLC 动态 IREM 快速近似封装影响；静态通常只要 R，动态必须补 L/C。Chapter 4 p.195-196, Chapter 7 p.272-273。
`REDHAWK_PKG` SPICE subckt 动态 IREM / Package 更真实的 RLCK 包装模型；子电路名必须是 `REDHAWK_PKG`。Chapter 7 p.274-275。
`compile_pkg` 输入集 Package Compiler 包模型、PLOC、GSR、电压文件、变换规则等，用于自动匹配 die/package pin 并生成 wrapped model。Chapter 7 p.279-281。
`EM_NET_INFO`、slew/toggle、DEF/DSPF` Signal EM 给信号网切换频率、输入过渡时间、负载、电容与时序信息。Chapter 11 p.370-389。

逐节点解释：原理、输入、用途、命令

下面把 IREM 分析拆成 10 个节点。每个节点都回答同一组问题：它在解决什么物理问题、你要交给它什么数据、这些数据被拿去做什么、跑完后应该得到什么。

Node 0 · 选择分析模式
Chapter 4 p.188, Chapter 11 p.370-381

先判断你要的是静态平均压降，还是动态瞬态压降，还是信号线 EM

原理

静态把功耗转成平均注流，动态把真实波形转成瞬态注流，Signal EM 则关心信号线与器件驱动电流是否超过线宽/过孔 EM 极限。

要准备的数据

  • 静态：功耗分配、GDS/tech/ploc。
  • 动态：额外要 `spcurrent/cdev`、state、STA、RLC package。
  • Signal EM：额外要 signal RC DSPF、slew/toggle、信号网 tracing 数据。

这些数据用来干什么

  • 决定 `perform analysis -static` 还是 `-vcd` 还是 `-signalEM`。
  • 决定是否必须先跑 APLMMX 波形预表征。

起步命令

setup analysis_mode signalEM
import gsr <file>
setup design
Node 1 · APLMMX 电学预表征
Chapter 3 p.64-75

APLMMX 把“网表里的器件”变成 Totem 能使用的电流/器件模型

原理

APLMMX 先理解器件层次和端口，再生成 probe 或直接根据尺寸/Idsat 建模。动态流里，APLMMX 是真实波形和 Totem 模型之间的桥。

必须准备

  • `TOP_CELL`、`TOP_XCELL_NAME`
  • `SPICE_NETLIST` / `LAYOUT_NETLIST` / `DSPF_NETLIST`
  • `DEVICE_MODEL_LIBRARY`
  • `VDD_PIN_NAME`、`GND_PIN_NAME`、`VDD`
  • `SPICE_SIMULATOR`、`TEST_BENCH_FILE`、`SIM_OUTPUT_FILE`

数据用途

  • 识别器件类型、名字映射、power/ground pin。
  • 给 probe 找到 testbench 里的层次前缀。
  • 把 `.fsdb/.raw/.tr0` 等波形回灌为 `spcurrent/cdev`。

关键命令

aplmmx -gds aplmmx.config
aplmmx -s aplmmx.config
aplmmx -n aplmmx.config
Node 2 · 静态 vs 动态 Characterization 细分
Chapter 3 p.64-67, p.128-133

静态更像“估算+分配”，动态更像“实测+回灌”

静态路径

  • `aplmmx -gds` 直接生成静态建模所需输出。
  • 如果没有完整功耗，可用 `CHARACTERIZE_IDSAT 1` 估算器件 drive strength 与 block power 模板。
  • 可生成 `adsRpt/<design>.bpa_file` 辅助静态 `BLOCK_POWER_ASSIGNMENT`。

动态路径

  • 先 `aplmmx -s` 生成 `.aplmmx` probe 文件。
  • 把 probe 插进 testbench 跑 Spice。
  • 再 `aplmmx -n` 生成 `.spcurrent`、`.cdev`、`.gdsmmx`。

常见关键字

  • `AUTO_SPICE_FINGER_SUPPORT 1`：自动处理 finger。
  • `PROBE_NO_PAR 1`：仿真器不支持参数化 probe 时使用。
  • `PROBE_MAP`：波形变量名与 probe 名不一致时修正映射。
  • `DEVICE_CURRENT_FILE`：支持 DCOP 驱动的静态分析。

你应该拿到的输出

  • `*.aplmmx`：probe 列表。
  • `*.spcurrent`：器件端口电流模型。
  • `*.cdev`：器件电学模型。
  • `*.gdsmmx`：器件位置/类型/相对驱动能力。
Node 3 · GDS2DB 物理建模
Chapter 3 p.137-148, p.185-187

GDS2DB 负责把版图、层映射与 net tracing 变成可提取的物理网络

原理

Totem 要在几何世界里知道每一根电源线、每个 via、每个器件 pin 到底连到了什么。GDS2DB 做的就是把 GDS + layer map 变成可计算的物理数据库。

必须准备

  • `GDS_FILE`
  • `GDS_MAP_FILE`
  • `TOP_CELL` 或 `TOP_CELLS`
  • `VDD_NETS` / `GND_NETS` tracing 定义
  • `NATIVE_GDS_SUPPORT` + GSR 的 `GDSII_FILE`

数据用途

  • 把 GDS 层号映射成工艺层名。
  • 从 text label 或坐标开始 tracing 电源网。
  • 创建器件 pin snapping 与金属/via 连通性。

调试抓手

  • `USE_TOP_LEVEL_TEXT_ONLY 1` 避免低层 label 误连。
  • 坐标 tracing 时用 `@ `。
  • layer map 最好带 datatype，避免假短路。
Node 4 · Package / Board 建模
Chapter 4 p.195-196, Chapter 7 p.271-281

动态压降里，封装不是修饰项，而是电源路径的一部分

原理

die pad 之外还有 pad wire、wirebond、package substrate、board。封装阻抗越大，动态噪声越容易被放大。

必须准备

  • 简单模型：pad / wirebond / package 的 RLC。
  • 复杂模型：`REDHAWK_PKG` 子电路。
  • `.ploc` 文件：pad 坐标 + domain + package 端口名。

数据用途

  • 简单模型用 `setup pad/wirebond/package` 直接注入等效参数。
  • 复杂模型用 `.ploc` 把 die pad 和 package port 对接。
  • `compile_pkg` 则负责 pin 匹配、passivity 检查、wrapped model 生成。

关键命令

setup pad -power -r 0.01 -c 0.5
setup wirebond -power -r 0.245 -l 1420 -c 5
setup package -r 0.001 -l 10 -c 10

compile_pkg -m pkg.sp -p die.ploc -vg demo.gsr -op die_out.ploc -om redhawk_pkg.sp
Node 5 · Power Calculation
Chapter 4 p.188-191

`perform pwrcalc` 先决定“电流该从哪里注进去、注多少”

原理

无论静态还是动态，Totem 都要先理解功耗分布。`pwrcalc` 会统计平均周期功耗并给出图形化分布与报告。

必须准备

  • 设计已经成功导入。
  • GSR 中的电压域、频率、功耗相关关键字。
  • 必要时额外有 LIB/STA/CLOCK_ROOTS/FREQUENCY。

产出有什么用

  • 得出功耗热区和总功耗分布。
  • 推荐 `DYNAMIC_SIMULATION_TIME`。
  • 给静态电流分配或动态仿真窗口提供依据。

命令

perform pwrcalc
import power <Power_Dir_Name>
Node 6 · Extraction 与 Gridcheck
Chapter 4 p.191-195

这一节点把“有图有电流”变成“真的可求解的网络”

原理

Static 主要要电阻网络；Dynamic 还要电感和电容。抽取完成后，`gridcheck` 先快速指出最弱的电源/地路径。

必须准备

  • GDS2DB 物理数据库已经可用。
  • 电源域、ground 域命名清晰。
  • 动态流需抽 VDD 与 VSS 两边，且加 `-l -c`。

数据用途

  • 提取 R 或 RLC。
  • 识别 floating pin、未驱动 net、缺失连接。
  • `gridcheck` 把最弱实例排出来，适合早期弱网定位。

命令

perform extraction -power -ground
perform extraction -power -ground -l -c
perform gridcheck
perform gridcheck -o grid.rpt -limit 200
Node 7 · Static IREM 分析
Chapter 4 p.196-201

静态分析的关键不是波形，而是“你怎样把功耗分配进网络”

原理

静态 IR 会把功耗或地电流分到电源网节点，然后在电阻网络上解压降。适合早期 floorplan、block 级或平均场景。

必须准备

  • Static GSR：`TECH_FILE`、`PAD_FILES`、`GDSII_FILE`、`VDD_NETS`、`GND_NETS`。
  • `BLOCK_POWER_FOR_SCALING` 或 `BLOCK_POWER_ASSIGNMENT`。

数据用途

  • `BLOCK_POWER_FOR_SCALING`：按 block 总功耗缩放。
  • `BLOCK_POWER_ASSIGNMENT`：对 region / hierarchy / MMX pin 精细分配。
  • `CHARACTERIZE_IDSAT 1` 可在功耗不全时生成辅助模板。

命令

import gsr user_data/RAM256.gsr
setup design
perform pwrcalc
perform extraction -power -ground
perform gridcheck
perform analysis -static
totem2 -f static.tcl
Node 8 · Dynamic IREM 分析
Chapter 4 p.202-205

动态分析要把“时序状态 + 瞬态电流 + 封装 RLC”放到同一次求解里

原理

动态 IREM 不是简单把 static 功耗换成 time-domain，而是需要真实或近真实的器件电流波形、状态窗口和封装网络共同参与求解。

必须准备

  • `APL_FILES`：`spcurrent` + `cdev`
  • `USER_STA_FILE`
  • `GSC_FILE`
  • `DYNAMIC_SIMULATION_TIME`、`DYNAMIC_TIME_STEP`
  • 必要的 pad/wirebond/package 参数

数据用途

  • STA 限定 timing window。
  • GSC 指定具体 switching state。
  • RLC package 决定芯片外部供电路径阻抗。

命令

import gsr user_data/RAM256.gsr
setup design
perform pwrcalc
perform extraction -power -ground
setup pad -power -r 0.0 -c 0.0 -ground -r 0.0 -c 0.0
setup wirebond -power -r 0.002 -c 30.0 -l 250.0 -ground -r 0.002 -c 30.0 -l 250.0
setup package -r 0.0016 -c 5.0 -l 25.0
perform gridcheck
perform analysis -vcd
Node 9 · Power EM 设置与检查
Chapter 4 p.207-214

EM 检查默认跟在 static/dynamic 后面，但精度取决于 limit 与温度设置

原理

静态 EM 基于平均电流密度，动态 EM 默认看 peak，也可以切换到 AVG/RMS。Totem 把实际电流密度与 tech/EM tech 文件的限制值做比较。

必须准备

  • `TECH_FILE` 里的 metal/via EM limit。
  • 可选 `EM_TECH_PEAK`、`EM_TECH_RMS`、`EM_TECH_AVG`。
  • `TEMPERATURE_EM` 或 `TEMPERATURES_EM`。

数据用途

  • 决定按 wire width、via cut 数、温度修正后的限值。
  • 控制 dynamic EM 用 peak 还是 avg/rms。

命令

perform emcheck
perform emcheck -mode [AVG | RMS | PEAK | all]
gsr set EM_MODE [rms | avg | peak]
Node 10 · Signal EM 扩展
Chapter 11 p.367-390

Signal EM 可以从同一套 APLMMX 思路出发，但追踪对象从 P/G 变成信号网

晶体管级流程

  • `aplmmx -sig -s`：生成信号相关 probe。
  • Spice 跑含 RC 的 signal net 波形。
  • `aplmmx -sig -n`：回灌波形并生成 signal EM 模型。
  • `perform analysis -signalEM`：检查信号线 Iavg/Irms/Ipeak 与 EM 违规。

必须准备

  • GDS、GDS map、带坐标的 DSPF。
  • testbench、Spice model、`SIM_OUTPUT_FILE`。
  • `EM_NET_INFO`、`INPUT_TRANSITION`、slew/toggle 信息。

cell-level Signal EM

  • 更接近静态流程：DEF + DSPF + timing + toggle + tech。
  • 典型命令：`setup analysis_mode signalEM` → `perform pwrcalc` → `perform extraction -signal` → `perform analysis -signalEM`。

最重要提醒

  • Signal EM 设计必须 short free。
  • `TEST_BENCH_FILE` 需要单独指定。
  • 若仿真器不支持参数化 probe，就设 `PROBE_NO_PAR 1`。

关键文件与输出物

学会 TOTEM IREM 的一个捷径，是先搞清楚每个文件到底扮演什么角色。下面按“你会看到什么产物”来倒推流程。

<cell>.aplmmx

APLMMX 生成的 probe 列表。动态 power 或 signal EM 做外部 Spice 仿真时，要把它 include 到 testbench 中。没有它，后面的 `-n` 就没有可导回的器件电流。

Chapter 3 p.64-65, Chapter 11 p.367-381
<cell>.spcurrent / <cell>.cdev

动态 IREM 的核心电学输入。`spcurrent` 保存器件端口电流模型，`cdev` 保存器件电学模型；两者一起通过 GSR 的 `APL_FILES` 导回 Totem。

Chapter 3 p.64-65, Chapter 4 p.202-204
<cell>.gdsmmx

把器件位置、类型、相对驱动信息和版图建模关联起来。你可以把它理解为“器件世界”和“几何世界”的桥接文件。

Chapter 3 p.64-65
gds2db.config / GDSII_FILE

`gds2db.config` 描述 GDS 抽取；GSR 的 `GDSII_FILE` 则告诉 Totem 在运行时用哪个 config 和什么视图模式导入物理模型。

Chapter 3 p.137-148
`.ploc`

简单时它只定义 die pad 坐标和 P/G 类型；有 package subckt 时，它还必须承担“die pad 名 ↔ package port 名”的映射职责。

Chapter 4 p.197, Chapter 7 p.278
GSR / TCL

GSR 是“你要分析什么设计、哪些模型、哪些域、哪些温度、哪些时序文件”；TCL 是“按什么顺序真正执行这些动作”。

命令执行配方

          

          
如果你只想快速记住“先跑什么、后跑什么”，可以直接看这三套配方。它们和前面的模板是一一对应的。

        

        

          

            
配方 A：静态 IREM

            
适合早期网格评估、平均压降、Block 或 Region 功耗分配。

            
    
              
  1. 准备 `gds2db.config` 和 `static.gsr`。
    2. 
              
  2. 在 Totem 中导入 GSR，建立设计数据库。
    3. 
              
  3. 跑 `pwrcalc` 得到功耗分布。
    4. 
              
  4. 跑 `perform extraction -power -ground`。
    5. 
              
  5. 跑 `perform gridcheck` 快速找弱网。
    6. 
              
  6. 最后 `perform analysis -static`。
    7. 
            

            

              

                手册命令骨架
              

              
import gsr user_data/RAM256.gsr
setup design
perform pwrcalc
perform extraction -power -ground
perform gridcheck
perform analysis -static
totem2 -f static.tcl

            

          


          

            
配方 B：动态 IREM

            
适合真实向量/状态驱动的 DvD、电源噪声和动态 EM。

            
    
              
  1. 写 `aplmmx.config`，先 `aplmmx -s` 生成 probe。
    2. 
              
  2. 把 probe 放进 testbench 跑 Spice。
    3. 
              
  3. `aplmmx -n` 生成 `spcurrent/cdev`。
    4. 
              
  4. 准备 `dynamic.gsr`，导入 `APL_FILES`、`USER_STA_FILE`、`GSC_FILE`。
    5. 
              
  5. 设置 pad/wirebond/package RLC。
    6. 
              
  6. `perform analysis -vcd`。
    7. 
            

            

              

                手册命令骨架
              

              
aplmmx -s aplmmx.config
# run spice with <cell>.aplmmx included
aplmmx -n aplmmx.config
totem -f dynamic.tcl

            

          


          

            
配方 C：Signal EM

            
适合把动态驱动电流投影到信号网上看 Iavg / Irms / Ipeak 的 EM 风险。

            
    
              
  1. 准备信号 RC DSPF、GDS、map、testbench、波形输出路径。
    2. 
              
  2. `aplmmx -sig -s` 生成 signal probe。
    3. 
              
  3. 运行 Spice，回灌 `SIM_OUTPUT_FILE`。
    4. 
              
  4. `aplmmx -sig -n` 生成 signal EM 模型。
    5. 
              
  5. `setup analysis_mode signalEM` 后执行 `perform analysis -signalEM`。
    6. 
            

            

              

                手册命令骨架
              

              
aplmmx -sig -s signal_em.aplmmx.config
# run third-party spice
aplmmx -sig -n signal_em.aplmmx.config
totem2 -f cmd_signalEM.tcl
